# 플레이어 가사 수명과 고정 크롬 — 1029

## 가사 추적

기존 LyricsView의 onAppear는 외부 presentationIsVisible 값이 true여도 먼저 setVisible(false)를 호출한 뒤 별도 task에서 400ms 후 다시 켰다. 회전으로 두 뷰가 교체되는 동안 이전 뷰의 onDisappear도 같은 모델에 setVisible(false)를 호출할 수 있었다. 따라서 화면에 새 가사가 있어도 추적이 꺼지는 경로가 있었다.

각 LyricsView와 FullPlayerView 호스트가 자신의 UUID로 표시 권한을 등록/해제한다. 이전 뷰는 새 뷰의 권한을 해제할 수 없으며 마지막 소유자가 사라질 때만 추적/번역 정리가 진행된다. 가사 표시 상태를 즉시 반영하고 400ms 지연을 제거했다. 호스트는 새 곡의 모델에도 현재 가사 표시·scenePhase 상태를 전달한다. 늦게 완료된 다른 곡의 load가 현재 표면을 바꾸지 못하도록 모델 동일성·곡 ID·취소 여부를 확인한다. 새 곡의 번역 세션은 곡 ID에 따라 교체한다.

## 세로 레이아웃

일반 글자 크기의 iPhone에서 재생·가사·큐가 하나의 portraitPlayer 계층을 공유한다. 진행 막대, 음질 배지, 재생 버튼, 볼륨, 출력 메뉴를 화면별로 새로 만들지 않는다. 윗부분 콘텐츠만 투명도와 터치/접근성 표시를 바꾼다. 가사 집중 보기에서 컨트롤을 숨길 때도 컨트롤 슬롯 자체는 유지하며 하단 가사·출력·큐 메뉴는 계속 표시한다.

하단 안전 영역을 포함해 출력 기기 이름이 홈 표시 영역 위에 들어오도록 footerCenter를 제한한다. 기존 18/24pt 진행 막대, 서로 다른 버튼 간격·볼륨 패딩·크롬 오프셋이 화면별로 혼용되던 경로를 통합했다. 큰 접근성 글자 크기에는 기존 유동 레이아웃을 유지한다.

## 배경과 손잡이

플레이어의 불투명 검정 바탕과 AppleMusicLyricsBackground 인스턴스는 표면 전환 중 유지한다. 몰입형 커버 아래의 Metal 배경은 가려져 있는 동안 렌더링을 쉬며, 가사·큐로 전환하면 같은 뷰가 재개한다. fullScreenCover의 presentationBackground도 검정으로 설정해 탭 화면이 투명한 중간 프레임으로 비치지 않도록 했다. 기존 전체 플레이어 진입/닫기 줌 전환은 유지한다.

상단 연장 이미지는 원본 시작점 아래까지 겹치게 연장하고 블러를 적용한다. 원본의 상단 6%를 그 위로 점진적으로 드러내 색/텍스처 차이가 수평선으로 드러나는 것을 줄였다. 닫기 손잡이는 공유 PlayerDismissHandle의 60×4pt 캡슐로 통일하고 그림자를 제거했다. 조작 영역은 88×44pt이다.

## 가로 번역 버튼

가로 가사 화면에서 번역이 필요한 가사가 로드되면 큐 버튼 중심과 같은 x축, 하단 메뉴에서 66pt 위에 번역 버튼을 오버레이한다. 메뉴의 높이나 간격을 바꾸지 않으며, 가사 스크롤 하단에는 버튼을 피할 여백을 둔다. 실제 번역/발음/서버 번역 메뉴 동작은 기존 공용 버튼을 사용한다.

## 검증

- 관련 macOS 테스트 29개 통과, 실패 및 런타임 경고 없음.
- 새 가사 수명 테스트: 겹친 뷰의 늦은 종료/중복 종료, 마지막 소유자 정리, 같은 곡에서 배경 복귀·일시정지 복귀·패널 재진입 후 추적.
- 렌더링 테스트: 상단 색 차이가 큰 커버의 연결, 손잡이 치수, 패널 변화 시 진행/재생/볼륨/메뉴 좌표 일치, 출력 기기 이름이 하단 안전 영역 안에 들어오는지 확인.
- 기존 가사 시킹·추적 캐시·번역/크롬·가로 레이아웃·가로 음질 배지 테스트 포함.
- iOS 앱/테스트 타깃 build-for-testing 성공, 새 경고 없음. git diff --check 통과.
- 합성 커버 렌더링을 확인했다. iPhone 런타임이 설치되어 있지 않아 실제 기기에서의 회전·터치·순간 탭 노출·실제 가사 공급원 동작은 직접 재현하지 못했다.
