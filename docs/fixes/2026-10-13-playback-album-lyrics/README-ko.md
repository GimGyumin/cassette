# 앨범 표시·재생 요청·Seek·가사 후속 수정

대상: 2026-10-13 홈/발견하기 및 이미지 정책 변경 이후의 코드. 기존 작업 트리와 기능은 유지했다. 이 문서는 이번 수정 범위를 기록하며, 이전 전체 감사 보고서를 대체하지 않는다.

## 검증

회귀 테스트와 iOS 빌드의 최종 결과는 같은 폴더의 `verification-results.txt`에 기록한다. 기존 테스트의 버퍼링/Seek/Gapless 시간 기준은 완화하지 않았다. 온라인 부분 목록을 먼저 보여주는 기존 테스트만 새 요구에 맞춰 바꾸고, 실패 시 다운로드 목록이 다시 표시되는 검증은 유지했다.

Xcode 27.2 beta의 macOS 테스트 호스트와 generic iOS 빌드를 사용했다. 원본 프로젝트의 기존 파일 조정 대기 문제를 피하기 위해 `/tmp/cassette-validation/Cassette.xcodeproj`를 사용했으며, 소스와 테스트는 현재 작업 트리를 심볼릭 링크로 참조한다.

iPhone/iPad는 CoreDevice에서 페어링 및 앱 조회가 가능했으나 `xctrace list devices`는 둘 다 Offline으로 보고했다. 조회 시 iPhone에 실행 중인 Cassette 프로세스도 없었다. iOS 시뮬레이터 런타임은 설치돼 있지 않았다. 따라서 수정한 앱의 실제 기기 실행, Instruments 추적, 화면 캡처 및 발열 비교는 수행하지 않았다. 기기에 앱을 덮어 설치하거나 앱 데이터를 삭제하지 않았다.

## 실제 기기에서 필요한 비교

동일한 Release 빌드 설정, 서버, 오디오 품질, 트랙, 네트워크 조건과 커버 캐시 상태로 수정 전후 각각 측정한다.

- 다운로드/캐시 없는 FLAC·ALAC·AAC·MP3를 20회 선택: 요청부터 첫 실제 오디오까지 시간, 타임아웃, HTTP 요청 수, 에러 분류 기록.
- Wi-Fi/셀룰러 각각 앞뒤 Seek 및 빠른 연속 Seek: 손을 놓은 시점부터 오디오 재개까지 시간, 실제 위치 오차, 마지막 요청 보존, Pause 중 Seek 확인. Range 지원·미지원 서버를 구별.
- 부분 다운로드 앨범과 콜드 커버: 부분 목록 노출 없이 전체 목록 표시, 배경 확정 전 덮개 유지, 이미지 없는 오프라인에서도 로딩 종료 확인.
- 커버 다운로드 중 강제 종료 후 재실행: 첫 유효 진행률이 디스크 저장 수를 반영하고 저장된 커버의 HTTP 요청이 반복되지 않는지 확인. 커버 캐시는 지우지 않음.
- 가사 10분 표시 및 일반 재생 30분: SwiftUI 업데이트 원인, Hitches, Time Profiler, Metal/GPU, Power Profiler, Allocations를 함께 비교. 간주·단어 가사·번역·대규모 라이브러리 스크롤 포함. 백그라운드와 Pause에서는 장식 렌더 및 가사 타이머가 멈추는지 확인.

이번 변경은 네이티브 Seek의 재개 대기와 상태 수명 문제를 고친다. 서버가 Range나 시간 오프셋을 지원하지 않아 완전한 파일 응답이 필요한 경우, 그리고 AudioStreaming 엔진에서의 실제 FLAC 파서 지연에는 별도의 실제 서버 측정이 필요하다. 네트워크나 디코딩 비용을 제거했다고 주장하지 않는다.

Apple 공개 권장사항: [AVPlayer의 자동 스톨 대기](https://developer.apple.com/documentation/avfoundation/avplayer/automaticallywaitstominimizestalling), [SwiftUI 성능 분석](https://developer.apple.com/documentation/xcode/understanding-and-improving-swiftui-performance), [Instruments의 SwiftUI 갱신 원인 분석](https://developer.apple.com/videos/play/wwdc2025/306/). Apple Music과 동등한 성능 또는 수치 개선은 주장하지 않는다.
