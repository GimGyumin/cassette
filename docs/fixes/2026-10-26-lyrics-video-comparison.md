# 실제 녹화 기준 가사 비교 및 수정

> 후속 작업으로 제공된 AMLL 소스의 실제 Swift 포트를 적용했다. 현재 엔진의 출처·범위·검증은 [AMLL Swift 포트](2026-10-26-amll-swift-port.md)를 참고한다.

## 비교 기준

사용자가 제공한 2026-10-25 녹화 두 개를 비교했다.

- 23:57:12 녹화: Cassette, 약 59.53초
- 23:56:23 녹화: Apple Music, 약 28.04초
- 두 영상 모두 1206×2622, 60fps, HDR PQ. 같은 가사 구간을 찾아 비교했으며 영상 시작 시각 자체를 동기 기준으로 쓰지 않았다. 음원의 표시 길이도 달라 영상 초 단위로 재생 타이밍을 덮어쓰지 않았다.
- AVFoundation으로 프레임을 추출했다. HDR 변환과 움직이는 배경 위상 차이가 있으므로 추출 이미지의 RGB 값을 그대로 앱 색상에 대입하지 않았다.

## 관찰과 변경

| 항목 | 녹화에서 확인한 차이 | 반영 |
| --- | --- | --- |
| 줄바꿈 | Cassette의 첫 줄에 단어가 더 많이 들어가 짧은 다음 줄이 생김 | 개별 토큰 배치를 문장 전체의 시스템 Text 조판으로 교체. 각 토큰의 시작·종료 시각은 TextAttribute로 유지 |
| 글꼴 | Cassette의 본문이 조금 작음 | 휴대폰 기본 36pt bold, 문장 내부 줄 간격 2pt |
| 비활성 가사 | Cassette의 인접 가사가 더 선명함 | 거리별 blur 2.4/3.2/4pt와 대비 조정 |
| 활성 줄 위치 | Cassette에서 컨트롤이 숨겨진 뒤 다음 활성 줄이 아래쪽에 자리 잡음 | 뷰포트와 실제 가사 블록 높이로 스크롤 앵커 계산. 화면 비율 대신 위쪽의 일정한 영역에 배치 |
| 헤더 버튼 | Cassette의 즐겨찾기·더보기 중심이 더 왼쪽 | 우측 여백 26pt, 액션 영역 44pt 및 사이 간격 4pt, 즐겨찾기 선 굵기 조정 |
| 이전·다음 버튼 | Cassette가 양쪽으로 더 벌어져 있음 | 재생 버튼 행 너비를 화면의 80%에서 73%로 조정 |
| 하단 가사 아이콘 | 선택 원과 내부 심볼 비율이 다름 | 선택 원 38pt, 심볼 20pt. 터치 영역은 유지 |
| 하이라이트 | 독립적인 조판 상자가 문장 간격에 영향을 줄 수 있음 | 하나의 문장을 조판한 뒤 글리프별 채우기·상승·glow를 그리도록 변경, glow 강도 완화 |

스크린샷의 공백 누락과 같은 결과를 만드는 구조화 가사 경로도 수정했다. 전체 부모 문장에 코러스가 함께 들어 있으면 메인 보컬의 토큰과 문자열이 일치하지 않아 기존 공백 복원이 실패했다. 각 보컬의 `CueLine.value`를 먼저 사용하고, 맞지 않을 때 부모 문장을 확인한다. 공백을 제외한 글자가 일치할 때만 복원하며 음절 시각은 바꾸지 않는다. 원문이 실제로 붙여 쓴 음절은 유지한다. 제공된 사진만으로 서버가 보낸 원본 가사까지 확정할 수는 없다.

## AMLL 참고

[재생 시퀀스](https://amll.dev/guides/component/sequence)와 [탐색 처리](https://amll.dev/guides/component/seeking)의 개념을 참고했다. 오디오 시각과 장식 애니메이션을 분리하고, 탐색 시 현재 시간으로 다시 맞추며, 사용자의 수동 스크롤을 유지한다. 기존 Cassette의 정지·숨김·저전력 갱신 정책은 유지했다.

[공백 정규화 옵션](https://amll.dev/reference/core/interfaceoptimizelyricoptions)의 연속 공백 정리와 누락된 단어 경계 복원은 다른 작업이다. 타이밍 간격이나 영어 사전으로 임의의 공백을 넣지 않았다. 외부 프로젝트의 구현 코드를 복사하지 않았다.
