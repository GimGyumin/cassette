# 가로 가사 화면 및 대화형 닫기 복원

사용자 제공 사진 중 `Bad (2012 Remaster)`가 표시된 Apple Music 화면을 기준으로 삼았다. 1280×588 화면에서 커버는 `(126, 85, 420, 420)`, 오른쪽 열 시작은 약 x=600이다.

## 변경 사항

- `PhoneLandscapePlayerColumns`가 전체 화면 좌표를 사용한다. 참고 사진의 커버·제목 위치와 34pt 가사 크기를 반영했다. 커버는 재생·정지 시 기존 73% 축소 애니메이션을 사용한다.
- 가사 영역은 화면 하단까지 이어진다. 툴바는 가사 위에 겹쳐 표시하고, 현재 줄의 스크롤 위치만 버튼 영역을 피한다. 버튼이 숨겨져도 커버·제목 위치는 유지한다. 번역 버튼은 왼쪽으로 이동하고 출력 장치 이름을 표시한다.
- 커버 탭을 재생·정지에 연결했다. 일반 세로·가로 화면, 가사 헤더 커버, 접근성 글자 크기 레이아웃에 적용했다.
- 손을 뗄 때 `closePlayer()`를 호출하던 별도 세로 드래그를 삭제했다. 기존 `navigationTransition(.zoom)`이 대화형 닫기를 담당한다. 커버의 곡 넘김은 UIKit recognizer가 시작하기 전에 가로 방향을 판별하여 세로 드래그를 차지하지 않도록 했다. 가사 스크롤 감지는 별도 DragGesture 대신 ScrollView의 phase를 관찰한다.
- 실제 보컬 활성 구간과 시각적 강조 구간을 분리했다. 짧은 공백에서는 이전 줄을 밝게 유지하다가 같은 가수의 다음 줄 시작 120ms 전에 100ms 페이드로 비활성화한다. 긴 간주·독립된 듀엣·코러스의 소스 타이밍은 유지한다.
- 내장 x-bg 코러스는 해당 타임스탬프 전후에 투명하며 접근성에서도 숨긴다. 독립 코러스 행도 활성 구간에서만 표시한다. 뒤로 탐색하면 미래 코러스가 다시 숨겨진다.

## 검증

- macOS: 관련 9개 suite, 43개 test 통과.
- 실제 SwiftUI 렌더링에서 가로 가사 열의 마지막 픽셀 행까지 영역이 이어지는지 확인했다.
- 내장 코러스는 999ms에 보이지 않고, 1500ms에 표시되며, 2000ms와 뒤로 탐색 후 0ms에는 보이지 않는지 픽셀로 검증했다.
- 다음 줄 직전 강조 해제, 긴 간주, 뒤로 탐색, 듀엣·코러스 독립 타이밍을 검증했다.
- iOS Simulator 대상 `build-for-testing` 성공. 실기기의 터치 전환과 프레임 속도를 실행 검증한 결과는 아니다.
- `git diff --check` 통과.
