# 1004 — Wi-Fi 무손실 전환 및 앨범 표시

## 변경 내용

- 셀룰러/유료 네트워크에서 일반 Wi-Fi로 바뀌면, 동일 곡의 압축 스트림을 원본 무손실로 전환할 수 있다. `isOnline`이 계속 true여도 동작하며, 백그라운드 재생 중에도 NWPathMonitor에서 전달한다.
- Wi-Fi 경로가 1.2초간 유지된 뒤 준비한다. Wi-Fi 음질 설정이 자동 또는 무손실이고, 원본 메타데이터가 무손실이며, 현재 스트림이 손실 변환 중인 경우에만 시도한다. 저데이터/유료 Wi-Fi, 로컬 파일, 라디오, 곡 끝부분은 제외한다.
- MediaResolver에서 같은 실제 재생 파일의 원본을 구한다. 손실 캐시를 재사용하지 않으며, 도중에 다른 Atmos 에디션으로 바꾸지 않는다. 서버·인증 헤더와 사용자의 명시적 재생 경로를 유지한다.
- 기존 스트림을 재생한 채 두 번째 AVPlayer를 무음으로 준비한다. 정확한 탐색과 preroll 후 실제 데이터가 계속 채워지게 하고, 무손실 코덱(FLAC/ALAC/PCM), 현재 위치의 버퍼, 두 시계의 정렬을 검증한다. 서버 timeOffset은 절대 곡 위치로 환산한다.
- 버퍼 2초 이상에서 시계를 정렬하고, 최소 1.5초 버퍼 및 25ms 이내 위치 차이를 연속 확인한 뒤 채택한다. 두 디코더가 이미 진행 중인 상태에서 80ms 선형 음량 전환을 적용한다. 대기 시간은 최대 12초로 제한한다.
- 실패하면 현재 소스를 유지한다. 일시정지·탐색·곡 변경·중지·시스템 중단·네트워크 역전 때 준비를 취소한다. 완료 직전에도 계정, 재생 명령, 곡, Wi-Fi 설정을 다시 확인한다. 전환으로 큐나 곡 태그, 재생 이력을 새 곡처럼 시작하지 않는다.
- AirPlay 외부 재생이 진행 중이면 두 플레이어의 출력 경로를 바꾸지 않고 현재 재생을 유지한다. 다음 곡을 불러올 때에는 정상 네트워크별 음질 정책이 적용된다.
- `[QUALITY-HANDOFF]` 로그로 준비·채택·기존 소스 유지 여부를 구분한다. URL이나 인증 값은 포함하지 않는다.

## 앨범 화면과 음질 라벨

사용자가 제공한 화면은 앨범 본문이 검게 비어 있고 상단 도구 영역만 남아 있었다. 코드에는 앨범 데이터와 별개인 커버 색상 준비까지 본문 전체를 덮는 로딩 오버레이가 있었다.

- 전체 본문을 덮는 오버레이를 제거했다. 제목·커버 영역은 즉시 표시하고, 곡 목록 영역에만 기존 skeleton을 사용한다.
- 색상 추출이 늦거나 취소되어도 데이터가 준비된 앨범을 숨기지 않는다.
- ViewModel이 생긴 직후 이름이 아직 빈 문자열인 경우에도 진입 때 받은 제목을 유지한다.
- 새로고침 중 기존 앨범 내용을 유지한다. 취소된 새로고침이 완료된 화면을 로딩 상태로 되돌리지 않도록 했다.
- 앨범 음질 라벨은 테마의 불투명 본문색, 플레이어 음질 라벨은 시간 표기의 반투명 보조색과 분리된 본문색을 사용한다.

스크린샷의 실제 기기에서 동일 상태를 재현한 것은 아니다. 위 변경은 본문을 가릴 수 있는 코드 경로와 라벨의 낮은 대비를 직접 수정한다.

## 검증

- 최종 재생·앨범 회귀 검증 86건 통과. 실제 HTTP 전환, 서버 오프셋 유지, 준비 실패/잘못된 코덱, 일시정지/탐색/곡 교체, 경로 역전/계정 변경, 명시적 압축 설정, 손실 캐시 우회, 새로고침 취소, 기존 gapless/크래시 경로를 포함한다.
- 오디오 분석을 켠 HTTP 전환도 통과했다. 테스트는 준비 중 기존 플레이어가 유지되고, 전환 전후 시계 손실이 80ms 미만이며, 이후 계속 playing인지 확인한다.
- `NativePlaybackMeterTests`는 다른 재생 테스트와 동시 실행할 때 1건 실패했다. 여러 테스트가 전역 `PlaybackBeatMeter.shared`의 활성 상태와 입력을 바꾸므로 단독 실행으로 분리했고, 같은 최종 바이너리에서 1건 통과했다. 전체 테스트 제품군을 한 번에 모두 실행해 통과했다는 의미는 아니다.
- 최종 macOS 테스트 타깃 컴파일과 iOS Simulator 빌드 성공. 빌드 로그에서 warning/error 없음. `git diff --check` 통과.
- 생성된 iOS 앱의 `CFBundleVersion=1004`, `CFBundleExecutable=Cassette-1004` 및 실행 파일 존재를 확인했다. 실기기에 설치하지 않았다.

검증 로그:

- `/tmp/cassette-1004-final-tests.log` — 회귀 86건 통과, 동시 실행된 미터 1건 실패
- `/tmp/cassette-1004-meter-tests.log` — 공유 미터를 분리한 단독 검사 1건 통과
- `/tmp/cassette-1004-final-ios.log` — 최종 iOS 빌드 성공

실제 셀룰러 기지국·Wi-Fi 전환, Bluetooth 출력의 청감, AirPlay, 잠금 화면 장시간 재생은 실기기 확인이 필요하다. HTTP 테스트는 로컬 서버와 실제 AVPlayer 디코딩·시계 연속성을 검증하며, 물리적 오디오 출력의 샘플 연속성이나 네트워크 단절 중 무조건 무중단 재생을 보장하는 측정은 아니다.

동기화 API의 요구 조건은 Apple 문서를 확인했다. `setRate(_:time:atHostTime:)` 호출 전에 자동 대기를 끄고, `preroll`은 준비된 정지 상태에서만 요청한다.

- [AVPlayer 시간 동기화](https://developer.apple.com/documentation/avfoundation/avplayer/setrate(_:time:athosttime:))
- [AVPlayer preroll](https://developer.apple.com/documentation/avfoundation/avplayer/preroll(atrate:completionhandler:))
