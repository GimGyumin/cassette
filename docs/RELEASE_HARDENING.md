# 출시 안정화 및 전력 최적화

2026-10-12 작업. 기존 기능과 진행 중인 변경을 보존하면서 다음 경로를 개선했다.

## 다운로드

- 음원 전송 전에 곡·서버·선택 음질을 파일 저널에 원자적으로 기록한다. 비밀번호, 토큰, 인증 URL은 기록하지 않는다.
- URLSession 완료 콜백 안에서 임시 파일을 영구 준비 영역으로 이동한다. 앱 프로세스가 사라져도 다음 실행에서 복원할 수 있다.
- 정상 완료와 복원은 같은 검증·변환·SwiftData 등록 경로를 사용한다. 데이터베이스 저장 성공 후 준비 파일을 지운다.
- 이전 다운로드를 새 파일로 교체할 때 이전 파일은 데이터베이스 커밋 이후 지운다.
- 계정 격리, 취소, 로그아웃 정리, 중복 완료를 처리한다. 준비 파일은 기기 백업에서 제외한다.
- OS가 유지한 전송의 완료 복구를 다룬다. 사용자가 앱을 강제 종료했을 때의 전송 지속이나 아직 시작하지 않은 앨범 나머지 곡의 재개를 보장하지 않는다.

## 배터리·발열·응답성

| 경로 | 변경 |
|---|---|
| 음원 다운로드 진행률 | 네트워크 청크마다 UI를 갱신하지 않고 최대 초당 4회, 완료 즉시 알림 |
| AAC 인코딩 | 여러 다운로드가 완료돼도 CPU 변환 작업은 한 번에 하나만 실행 |
| 자동 추가 다운로드 | 저전력, 발열, 메모리 압박, 백그라운드에서는 시작을 미룸 |
| 명시적 앨범/재생목록 다운로드 | 시작 시 기기 상태에 따라 동시 전송을 3개 또는 1개로 제한 |
| 다운로드 조회 | MainActor에서 서버 전체 레코드를 불러오던 경로를 서비스 내부의 ID 제한 조회로 변경 |
| 가사 추적 | 매 프레임 간주 위치를 선형 탐색하던 부분을 이진 탐색으로 변경 |
| 세션 저장 | 정기 저장 작업의 생성·취소 소유권을 PlaybackCheckpointScheduler로 분리 |
| SwiftData 세션 컨텍스트 | 작업별 동기 컨텍스트를 사용하여 임의 actor의 장기 컨텍스트 보유를 제거 |

기존 갭리스와 오디오 상태 확인은 유지한다. 프레임·전력 제한 정책은 PerformanceBudget에서 결정한다.

## 검색과 번역

- 첫 인덱싱이 진행 중이어도 서버 검색 결과를 표시한다. 인덱스가 준비된 뒤의 검색은 로컬 경로를 사용한다.
- 번역 제공자의 원시 오류를 화면에 출력하지 않는다. 재시도 가능한 오류와 설정/모델 문제를 구분한다.
- 사용자 지정 번역 실패 시 해당 곡에서 기본 번역을 선택할 수 있다. 저장된 사용자 프롬프트는 보존한다.
- 오류 안내를 닫을 수 있으며 원문 가사는 유지한다.

## 검증 경로

- macOS 회귀: `xcodebuild test -project Cassette.xcodeproj -scheme CassetteTests -destination 'platform=macOS' -parallel-testing-enabled NO CODE_SIGNING_ALLOWED=NO`
- iOS 컴파일: `xcodebuild build-for-testing -project Cassette.xcodeproj -scheme CassetteUITests -destination 'generic/platform=iOS Simulator' CODE_SIGNING_ALLOWED=NO`
- UI 통합: `python3 ci_scripts/ui_fixture_server.py`를 실행한 뒤 iPhone 시뮬레이터에서 `CassetteUITests` 실행.
- 합성 서버를 이용한 로그인→검색→재생→다운로드→서버 중단→로컬 재생 검증을 추가했다. 실제 계정이나 음악 라이브러리가 필요 없다.
- CI에 iOS 단위 테스트와 화면 테스트, 실패 시 xcresult 보관을 추가했다.

### 이번 실행 결과

- macOS 전체 회귀: **1,026개 테스트 / 182개 suite 통과** (직렬 실행). 다운로드 복구·계정 격리·ID 별칭 조회·최초 검색·번역 오류·전력 정책 회귀를 포함한다.
- iOS 앱 및 UI 테스트 `build-for-testing`: **arm64 / x86_64 시뮬레이터 대상 컴파일 성공** (Xcode 27.2 beta). 앱 코드 컴파일 경고는 없고, UI 테스트 대상의 App Intents 메타데이터 추출 생략 안내만 있었다.
- 합성 서버 자체 검증: 인증, 페이지 종료/바이트 범위, 서버 중단 후 요청 집계 **3개 통과**.
- 앞선 실행에서는 실제 오디오 장치를 쓰는 갭리스 시간 검증이 실패했다. 같은 실행에 장치 과부하 로그가 있었고 최종 전체 실행에서는 두 엔진 모두 통과했지만, 원인을 환경으로 확정하지 않는다. 임계값은 완화하지 않았다.
- iOS UI 통합 테스트는 이 환경에서 미실행이다. 사용 가능한 시뮬레이터가 없었고 신규 생성이 승인되지 않아, 컴파일과 CI 실행 경로 준비까지 검증했다. CI 자체도 아직 실행하지 않았다.

## 실기기 출시 판정

컴파일과 단위 테스트만으로 배터리 절감률이나 발열 개선 폭을 확정하지 않는다. 같은 기기·밝기·네트워크·음원·음량에서 변경 전후 각각 20분 이상 비교한다.

1. 화면을 잠근 스트리밍과 다운로드 음원 재생: CPU wakeup, 에너지 사용, 다음 곡 전환.
2. 가사와 앨범 배경을 표시한 재생: CPU/GPU, 메모리, 프레임 지연, thermalState.
3. 큰 앨범 다운로드와 AAC 변환 중 재생: 동시 인코더 수, 오디오 끊김, 열 상태 복구.
4. 저전력·통화 인터럽트·오디오 출력 변경·백그라운드 복귀.
5. 다운로드 도중 OS 프로세스 종료 후 재실행: 파일과 데이터베이스 일치, 중복 등록 없음.

PlayerService의 전체 상태 소유권 분리는 완료된 것이 아니다. 이번 변경은 정기 체크포인트 작업을 먼저 분리한 범위다.
